# 戦略単位の高速研究: 実装計画

## 実行単位
1 family = 仮説・設計 + 1つのパラメータ化された戦略実装 + 宣言した全組合せ。
高コストモデルは前回ファミリー全体の結果を解釈し、次の仮説と有限の探索空間を設計する。
低コストモデルは共有部品を再利用して実装を1回行い、Pythonが全組合せを実行・集計する。
微小なパラメータ差のためにモデル呼出しや戦略実装を繰り返さない。

## パラメータ空間
値リスト、開始・終了・刻みの包含範囲、条件別variants、明示的な比較制約を使用する。
戦略パラメータと約定・コスト設定を別の名前空間で保持する。
全組合せを実行する。実行上限で中断した場合はpartialとして記録し、残りを再開する。
無断のサンプリング・上位候補だけの記録・「部分実行を完了扱い」は行わない。

## 再利用
共通機能はsrc/n225m_bt/components/へ直接蓄積する。
@componentメタデータをASTで抽出し、関数・クラスのAPI、用途、コードハッシュをカタログ化する。
戦略も共有ソースに置く。実行フォルダは監査のための独立実装ではなく、自動保存される再現用記録。
毎回の設計・実装プロンプトには最新カタログを渡す。部品の登録審査は設けない。

## 段階
1. 方針変更・有限パラメータ空間・再利用部品・カタログ。
2. 固定データ参照・任意戦略バッチ・結果キャッシュ・中断再開・全パラメータのCSV/JSON集計。
3. 設定済みCLIを呼ぶ設計/実装ロール・戦略単位の自動ループ・共通部品の再発見。
4. 回帰テスト・合成データ実行・利用手順・GitHub反映。

## 検証
通常の研究ループに事前審査、データ再監査、全テストを要求しない。
基盤変更そのものには対象テストを実行する。
coverage、失敗を含むパラメータ別結果、周辺領域の集計、月別成績を保存する。
探索結果は独立した検証の証明ではない。繰り返し参照した期間を未使用holdoutと呼ばない。

## 今回の対象外
実データの提供・再取込、CLIのインストールや認証、本番発注、大規模分散基盤、Web UI。
この実行環境にユーザーのCLI認証・ローカル相場データはないため、実モデル/実相場での研究成績は検証しない。
